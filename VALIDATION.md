# Проверки 0.8.0

Дата: 2026-11-04. Проверяется новая архитектура с последовательными блоками Python, рабочей директорией `/project` и полным доступом к выбранной папке через стандартные библиотеки.

## Проверено

- **22 основные группы — PASS**, результаты в `tests/last-results.json`. Разбор Python и обычного финала, отклонение старого/неоднозначного формата без частичного исполнения, границы путей/вкладок, очередь сохранения и её восстановление, отсутствие повторных запросов разрешения, последовательный цикл, защита от повторного exchangeId, прерывание без повторного исполнения, пауза/остановка, ошибки/таймауты, восстановление уже отправленного запроса без повторной отправки, отмена запуска во время подготовки, пауза при ошибке сохранения.
- **Сквозной сценарий — PASS**: тестовая модель возвращает один Python-блок; настоящий Worker/Pyodide через настоящий CDP читает две HTML-фикстуры, разбирает их локальным BeautifulSoup, получает три документа, пишет `corpus.jsonl`, `coding.csv`, `report.md` и checkpoint в корень OPFS. Сохраняются URL, время, текст и хеш, проверяются цитаты и количество. Одна рабочая вкладка переиспользуется. Модель получает только итоговую сводку, затем обычным текстом завершает задачу. Обязательные служебные папки/снимки не создаются.
- **Настоящий Pyodide/OPFS — PASS**: cwd `/project` перед каждым блоком, существующие и внешне добавленные файлы, перезапись, вложенные папки, rename/delete, flush/truncate, локальный BeautifulSoup, тёплый Worker без повторных загрузок. Сохранение перед browser await, сохранение при исключении и после прекращения бесконечного цикла, файлы после reload, синтаксическая ошибка до пользовательских побочных эффектов. Ошибка mount сбрасывает частично подготовленный Worker; повторный запуск с правильной папкой проходит.
- **Worker/WASM — 7 групп PASS**: молчащий/отклонённый Worker, ошибка загрузки WASM, медленный запуск с отдельным диагностическим бюджетом кода, выборочные пакеты, отсутствие streaming и неправильный MIME, отмена загрузки. Автоматического общего таймаута Python нет.
- **PyPI/CDN — 5 групп PASS**: реальная установка закреплённого python-slugify с зависимостью, wordcloud 1.9.3 с PNG в папке, повторное использование, ограничения адресов/GET/SHA-256 и отмена загрузки. TLS проверяется, proxy/сертификаты не обходятся.
- **CDP и scripting — PASS**: DOMContentLoaded, задержанный контент и геометрия, исключение часов из стабилизации, busy/таймаут/отмена, очищенный HTML без скрытых полей и CSS-hidden текста, взаимодействия по селектору, замена текста вместо дописывания, ожидание элемента, переиспользование и явная новая вкладка.
- **Связка чата/исполнителя — PASS на искусственном интерфейсе**: исходники service worker и executor, закрытые настройки, настоящий Python Worker → запись в OPFS → обычный финал, читаемая история, скачивание, остановка и «продолжай» без настроек, освобождение простаивающего интерпретатора при переходе в другой чат. Использован также touch viewport, что не является проверкой Titanium на устройстве.
- **DOM/история/прокрутка — PASS**: восстановление pre/code с Python, несколько блоков не склеиваются, одинаковые ответы различаются ключами сообщений, неподтверждённый пример не скрывается, финал остаётся обычным текстом. Перестроение DOM сохраняет историю и исходный ответ для адаптера. Пройдены wheel/touch-прокрутка без сброса вниз, светлая/тёмная темы, компактная панель, обычный чат и мастер привязки.
- **Сохранённый DOM DeepSeek — PASS для эвристик адаптера**: автоматическое нахождение поля/отправки/ответа/кнопок, запрет неизвестной иконки, признаки завершения. Это исторический экспорт; в нём не проверено новое живое представление Python-блоков.
- **Статический manifest/CSP — 6 проверок PASS**; JS и Python API проходят синтаксическую проверку. Локальные зависимости сверяются по официальным SHA-256 при упаковке.

## Что не проверено

**В этой версии не выполнена живая проверка авторизованного DeepSeek.** В среде нет настроенного тестового аккаунта; домены DeepSeek не разрешены сетевой политикой. Установка сторонних unpacked-расширений запрещена управляемой политикой Chromium. Эти ограничения не обходились.

Автоматические стенды используют локальный HTTP origin и мост Chrome API. Worker, WASM, Python, CDP, OPFS и IndexedDB настоящие, но это не проверка extension-origin установленного расширения. Нативная папка Windows/macOS с пользовательским выбором и восстановлением разрешения, живой чат и Titanium на устройстве остаются для ручной приёмки. OPFS использует настоящий FileSystemDirectoryHandle, но не заменяет эту проверку.

## Ручная приёмка перед релизом

1. Загрузить папку 0.8.0 в Chrome Windows/macOS, обновить DeepSeek, войти и выбрать отдельную папку результатов.
2. Попросить создать `hello.txt` в корне, прочитать его обратно и вывести итог. Убедиться в последовательном исполнении обычного блока `python` и обычном финальном ответе.
3. Попросить изучить DOM сайта и собрать данные с нескольких страниц одним Python-сценарием; проверить переиспользование вкладки, полноту, отсутствие дублей и фактическое количество строк.
4. Проверить перезапись выбранного тестового файла, rename/delete, чтение ранее существующего CSV, график и установку пакета через micropip.
5. Остановить долгий сценарий после checkpoint; проверить файлы. Обновить страницу и продолжить через чат без повторного сбора уже сохранённых записей.
6. Проверить ручную прокрутку истории, смену чата/папки, отзыв/восстановление разрешения, CAPTCHA или ограничение DeepSeek. Убедиться, что запрос не отправляется повторно при неопределённости.

До этой приёмки ZIP является проверенной на локальных стендах предварительной версией. Тег релиза автоматически не создаётся.
