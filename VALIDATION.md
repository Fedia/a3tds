# Результаты проверки

Дата: 1 ноября 2026. Среда: Linux, Chromium 154.0.8037.57. Windows и macOS непосредственно не проверялись.

## Выполнено

- Разобран manifest.json; все собственные JS-модули прошли `node --check` (только разработческая проверка, пользователю Node не требуется).
- Проверены наличие локальных ресурсов, JS/WASM, stdlib и зависимостей Pyodide 0.27.7. SHA-256 всех 14 wheel-файлов совпал с официальным `pyodide-lock.json`. Дополнительный SHA256SUMS фиксирует скачанные файлы runtime.
- Собственный JS не использует eval / new Function / вставку исполняемого удалённого кода. CSP extension_pages разрешает только локальные скрипты и WASM. Python изолирован непрозрачным origin sandbox и отдельным Worker. Blob-bootstrap содержит только постоянные локальные URL; Python-код туда не подставляется.
- В Chromium выполнены 13 групп проверок из `tests/tests.js`. Машинный результат — `tests/last-results.json`.
- Отдельно проверена инициализация рабочей страницы: поле задачи, поля селекторов, кнопка запуска и загрузка модулей без JS-ошибок.

### Как выполнялись браузерные тесты здесь

Временный разработческий HTTP-стенд обслуживал те же исходники и фикстуры. Playwright предоставлял тестовый транспорт для `chrome.tabs`, `chrome.scripting`, `chrome.storage` и `chrome.debugger`: вызовы CDP действительно исполнялись браузером через его CDP-сессии, а не возвращали заранее заданный DOM. Для File API использована настоящая OPFS Chromium; для состояния — настоящий IndexedDB. Pyodide, WASM, pandas, matplotlib и Worker исполнялись настоящим браузером, с CSP, соответствующей ограничениям продукта. В sandbox-стенде только схема локальных ресурсов была HTTP loopback вместо chrome-extension. Проверка HTTP-стенда не подтверждает доступность тех же ресурсов и Chrome API из установленного расширения.

Транспорт стенда не включён в основной интерфейс. Пользователь запускает `tests/index.html` внутри расширения без сервера, npm, системного Python или Playwright. Тестовая модель существует только в модуле тестов и не предлагается как подключённый DeepSeek.

### Что покрыто

1. JSON-протокол: правильная команда; лишние поля, неверные типы, неизвестный tool и опасный id отклоняются.
2. Пути: traversal, абсолютные пути, обратные слеши, недопустимые Windows-имена.
3. URL: служебные схемы, DeepSeek, credentials и потенциальные секреты в query/fragment.
4. IndexedDB, File API, сохранение пользовательского файла при конфликте, обновление собственного файла, отзыв разрешения.
5. Восстановление незавершённой команды и таймаут Promise.
6. BrowserTools через настоящий CDP: открытие, snapshot, текст, ссылки, таблицы, запрет посторонней вкладки, клик, изменение DOM, запрет старого snapshot, ввод и переход на страницу пагинации.
7. Chat fixture: вставка, отправка, генерация и завершение; полный DeepSeekAdapter.exchange с журналированием; неопределённое нажатие submit не повторяется автоматически.
8. Настоящий Pyodide: pandas, statistics, matplotlib Agg, PNG и недоступность IndexedDB/Chrome API из Python Worker.
9. Python: timeout холодного старта и отмена уже начавшегося бесконечного вычисления после сигнала running; Worker завершается.
10. Сквозной AgentController с тестовой моделью: snapshot → corpus.add → повтор того же id → Python → analysis.save → task.finish. Проверены corpus.jsonl, coding.csv, report.md, prompts.json, task-state.json, частоты, версия схемы и хеш восстановленного корпуса.
11. Цитата, отсутствующая в исходнике, отклоняется до записи разметки.
12. Пауза сохраняет полученный ответ без исполнения; продолжение исполняет его; stop не допускает следующего шага.
13. Исправление JSON ограничено двумя повторами; незавершённая команда блокирует запуск до ручной сверки.

При принудительной остановке Worker браузер прерывал загрузку assets: тестовый HTTP-сервер сообщал ConnectionResetError. Это ожидаемый результат отмены. Отдельный 404 favicon не относится к ресурсам расширения. Ошибок тестов в итоговом прогоне нет.

## Реальный DeepSeek

**Не проверен.** Нет доступа к авторизованному аккаунту, не наблюдалась текущая разметка. Селекторы не заполнены вымышленными значениями. Реализован настраиваемый DOM-адаптер и диагностика. Для проверки требуются самостоятельно авторизованная вкладка пользователя и селекторы её текущего интерфейса, включая реальные признаки входа, CAPTCHA, лимита и завершения. В README приведён порядок короткого вертикального теста, затем исследовательского сценария.

## Установка расширения

**Заблокирована средой.** Обычный запуск Chromium с unpacked-папкой не загрузил расширение. Диагностический вызов `Extensions.loadUnpacked` вернул:

> Loading of unpacked extensions is disabled by the administrator.

Это административная политика тестового Chromium. Она не обходилась. Поэтому не подтверждены:

- принятие manifest/CSP конкретной установкой Chrome;
- боковая панель и `chrome.debugger` именно из extension-origin;
- загрузка sandbox Worker и vendor через chrome-extension web_accessible_resources;
- реальный диалог выбора пользовательской папки (OPFS покрывает реализацию файловых операций, но не picker);
- перезапуск всего браузера с сохранением handle и восстановлением разрешения;
- целевые Windows/macOS.

## Критерии готовности

| Критерий | Статус |
|---|---|
| Папка загружается как unpacked | Подготовлена; фактическая загрузка здесь заблокирована политикой |
| Авторизованный DeepSeek подключается | Код/диагностика есть; необходима ручная настройка и проверка |
| Последовательные шаги агента | Пройдены с тестовой моделью; с DeepSeek не проверены |
| Страница, взаимодействие, файл, Python | Пройдены на стенде; Chrome API в extension-origin требуют проверки |
| Корпус, CSV, отчёт | Созданы и проверены в OPFS на фикстуре |
| Контролируемые ошибки, пауза, stop | Пройдены тесты; реальные ограничения сервиса не наблюдались |
| Сохранность после перезагрузки | Проверено чтение IndexedDB и recover; полная перезагрузка расширения/браузера требует ручной приёмки |

Готовность на реальном DeepSeek и целевых ОС не заявляется. Независимые части реализованы; оставшиеся шаги перечислены в ручной приёмке README.
