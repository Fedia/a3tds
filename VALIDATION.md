# Проверка версии 0.2.0

Дата: 1 ноября 2026. Среда: Linux, Chromium 154.0.8037.57. Titanium на реальном устройстве, Windows/macOS и авторизованный DeepSeek не были доступны.

## Результаты

- 14 групп проверок из tests/tests.js прошли. Машинный отчёт — tests/last-results.json.
- tests/dev/mobile-engine.py прошёл: viewport 390×844, touch-эмуляция, настройки закрываются, цикл продолжает работать в iframe чата, настоящий Python Worker считает сумму 6, OPFS сохраняет результат, повторно открытые настройки скачивают его. Содержимое скачанного JSON сверено. Прямое сообщение executor-command из контекста чата отклоняется. Выключение переключателя останавливает задачу с бесконечным Python.
- tests/dev/touch-ui.py прошёл: отправка касанием и Enter перехватывается, обычный чат при выключенном агенте работает, четыре касания сохраняют привязки, экранная кнопка отменяет мастер, программная отправка адаптера не перехватывается повторно.
- Совместимый transport chrome.scripting отдельно проверен: snapshot, ввод, click, инвалидирование идентификаторов после изменения DOM. Полномочия ограничены вкладками задачи.
- Настройки укладываются в мобильный viewport без горизонтального переполнения, включая список файлов.
- Собственные JS-модули прошли node --check. Node не требуется пользователю.
- Все 14 wheel-пакетов совпадают по SHA-256 с официальным pyodide-lock.json. ZIP упакован локально; контрольные суммы вложенных файлов сформированы упаковщиком.

## Состав 14 групп

1. JSON: корректная команда, запрет лишних полей/инструментов и опасных id.
2. Пути: traversal, абсолютные пути, недопустимые Windows-имена.
3. URL: служебные схемы, модель, credentials и query/fragment.
4. IndexedDB/File API: сохранение, конфликт пользовательского файла, собственный файл, отзыв разрешения.
5. Восстановление незавершённой операции и таймаут.
6. BrowserTools через CDP: открытие, snapshot, текст/ссылки/таблицы, клик, ввод, пагинация, устаревший DOM, запрет чужой вкладки.
7. Совместимый BrowserTools через scripting без CDP.
8. DOM чат-фикстуры и полный DeepSeekAdapter.exchange, журналирование до отправки, отсутствие автоматического повтора неопределённой отправки.
9. Настоящий Pyodide: pandas, statistics, matplotlib Agg, PNG, недоступность IndexedDB/Chrome API из Python Worker.
10. Python: timeout запуска и прерывание уже выполняющегося вычисления после сигнала running.
11. Сквозной AgentController с тестовой моделью, защита от дубликатов, сохранение файлов и состояния. Legacy corpus/analysis обработчики покрываются для совместимости; в новом системном промпте они не рекламируются.
12. Отклонение недостоверной цитаты в legacy-инструменте.
13. Пауза, продолжение и остановка.
14. Ограничение исправлений JSON и блокировка неопределённой команды до ручной сверки.

## Методика и её пределы

Распакованные расширения запрещены политикой администратора установленного Chromium. Диагностический вызов Extensions.loadUnpacked ранее вернул: `Loading of unpacked extensions is disabled by the administrator`. Запрет не обходился.

Поэтому стенды используют HTTP loopback и транспорт Playwright вместо Chrome API установленного расширения. Код service-worker.js, executor.js, контроллера, DOM-адаптера и Python исполняется настоящим Chromium; программные вызовы вкладок и runtime доставляются тестовым мостом. CDP действительно выполняется браузером. File API/OPFS, IndexedDB, iframe, Worker, WASM и Python настоящие. Для sandbox используется CSP с теми же ограничениями, но локальные HTTP-ресурсы заменяют chrome-extension URL.

Это подтверждает логику маршрутизации, изоляцию Python и независимость от вкладки настроек в стенде. Это не подтверждает работу web_accessible_resources, CSP и API конкретного мобильного расширения. Отдельные 404 favicon и сбросы HTTP-соединения при принудительной отмене Worker — ожидаемое поведение тестовой среды.

Разработческие тесты воспроизводимы из tests/dev. Они требуют Python/Playwright только у разработчика. Для пользователя тесты tests/index.html запускаются внутри расширения без npm, системного Python или сервера.

## Оставшаяся ручная приёмка

1. Загрузка расширения в Titanium, проверка версии Chromium и отсутствия ошибок manifest/CSP.
2. На странице DeepSeek появляются только переключатель и настройки; диагностика видит исполнитель в iframe. Настройки закрываются, задача продолжается.
3. Выбор внутреннего хранилища, привязка элементов касаниями, сквозная задача в авторизованном чате и скачивание результата на телефон.
4. Проверка CDP; при отсутствии — стандартный transport с выданным доступом к сайтам. Некоторые сайты отклоняют программные события.
5. Признаки генерации/завершения, реальная CAPTCHA, вход и лимиты DeepSeek. CAPTCHA не обходится; неопределённые состояния должны приводить к паузе.
6. Перезапуск/выгрузка мобильного браузера, восстановление состояния и отсутствие повторного исполнения незавершённых действий.

На Android следует оставлять DeepSeek на экране. Исполнитель во вкладке чата не защищает от завершения приложения ОС, блокировки телефона или нехватки памяти. Полная совместимость Titanium и живого DeepSeek пока не заявляется.


## 0.2.1 — распознавание чата

Добавлены проверки автоматического обнаружения, устаревших и невалидных селекторов, неоднозначной отправки, отсутствующего признака завершения и сообщения об ограничении сервиса (`tests/dev/chat-discovery.py`). Пройдены также touch-ui.py и mobile-engine.py. Это синтетические страницы в Chromium, не настоящий DeepSeek. Причина потери привязки на устройстве пользователя не воспроизведена; обязательная проверка наличия четырёх селекторов удалена, добавлен общий распознаватель и восстановление сохранённых настроек.


## 0.2.2 — сохранение ручной привязки

Мастер переводит касание SVG в выбор внешнего элемента управления. Селекторы проверяются по совпадению с выбранным DOM-элементом; запасной путь привязан к корню и не зависит от пространства имён SVG. Выбор одной кнопки вместо текста и кнопки ответа даёт отдельную понятную ошибку. Локальная конфигурация обновляется только после успешной записи в storage.

Пройдены chat-discovery.py (SVG, безымянные соседние элементы, относительные пути), touch-ui.py (полный мастер с SVG-кнопкой без атрибутов, сериализация и чтение сохранённой привязки) и mobile-engine.py. Реальное устройство пользователя недоступно; подтверждён источник сообщения в коде, но точный DOM, вызвавший ошибку на Titanium, неизвестен.


## 0.2.3 — пользовательский экспорт реального DeepSeek

Проверен предоставленный пользователем outerHTML от 01.11.2026 в Chromium, с удалёнными скриптами и заблокированной сетью. Распознаны textarea, круглая primary-кнопка с SVG отправки, `ds-assistant-message-main-content` и SVG копирования в панели ответа. Класс `ds-button--disabled` и aria-disabled учитываются перед нажатием. Незнакомая иконка primary-кнопки блокирует отправку и принятие ответа. Эти признаки основаны на полученном DOM; настоящая иконка остановки, CAPTCHA и ошибки сервиса этим снимком не подтверждены.

`tests/dev/deepseek-observed.py` проверяет исходный экспорт (путь можно передать аргументом), а по умолчанию — `fixtures/deepseek-observed.html`. Фикстура содержит только нужную структуру, классы и SVG; переписка заменена искусственными данными, удалены ссылки, профиль, скрипты и ресурсы. В репозиторий пользовательский файл не добавлен. Дополнительно имитируется полный цикл адаптера: вставка → изменение доступности div-кнопки → клик → изменение иконки → новый ответ при постоянном количестве DOM-сообщений → завершение с журналом. Это имитация поведения сайта на настоящей структуре DOM, а не живая отправка DeepSeek.

Также пройдены chat-discovery.py, touch-ui.py и все 14 групп основной проверки (включая Python и сквозной сценарий). Прежние проверки живого DeepSeek/Titanium остаются непроведёнными.
