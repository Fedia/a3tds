# ПсихоАгент MVP 0.1

Расширение Chrome Manifest V3: веб-чат DeepSeek → JSON-команда → инструменты браузера / файлов / Python → результат обратно в чат. Исходники — обычные ES-модули, HTML и CSS. Папка с этим README является папкой расширения; сборки, npm, сервера и системного Python для использования нет.

**Статус:** реализован и проверен на локальном браузерном стенде. Реальный авторизованный DeepSeek не был доступен. Его DOM-селекторы намеренно не выдуманы: перед первым запуском нужно настроить и проверить их в своём интерфейсе. В среде разработки загрузка unpacked-расширений запрещена политикой администратора. Поэтому загрузка именно как расширения, Chrome API в extension-origin и сквозной сценарий с реальным DeepSeek остаются ручными приёмочными проверками. Все 7 критериев готовности из задания пока не подтверждены. Подробности в `VALIDATION.md`.

## Установка Windows и macOS

1. Распакуйте архив в постоянную папку, например `Documents/psy-agent`. Не открывайте расширение прямо из ZIP. На Windows рекомендуется короткий путь без чрезмерно длинных родительских папок.
2. Откройте обычный Chrome версии 120 или новее. Введите `chrome://extensions`.
3. Включите «Режим разработчика» → «Загрузить распакованное расширение» → выберите папку **с manifest.json**, а не её родительскую папку.
4. Закрепите «ПсихоАгент MVP» через меню расширений. Нажмите значок → «Открыть управление» в боковой панели.
5. Chrome покажет предупреждение о разрешении debugger: оно необходимо для CDP без отдельного порта отладки. Расширение программно ограничивает управление вкладками, которые создало для задачи. Не закрывайте рабочую вкладку во время выполнения.

На Windows и macOS шаги одинаковы; `Ctrl` и `Command` при редактировании файлов зависят от ОС. На корпоративном устройстве администратор может запретить распакованные расширения или debugger. Это блокировка установки, обход в MVP не предусмотрен.

## Первый запуск

1. Нажмите «Выбрать папку проекта» в **рабочей вкладке**. Выберите новую отдельную папку результатов, например `Documents/research-results`. Не выбирайте папку расширения, домашнюю папку или каталог с секретами. Разрешите чтение и запись.
2. Откройте `https://chat.deepseek.com`, самостоятельно войдите и создайте новый чат. Не используйте в этой вкладке другой разговор во время работы агента.
3. Обновите список вкладок в управлении. Выберите DeepSeek. Настройте селекторы по инструкции ниже, нажмите «Подключить / диагностика».
4. Прочитайте описание передачи данных и установите флажок согласия. Во внешний чат передаются тексты только рабочих страниц, задача, явно разрешённые фрагменты файлов и результаты инструментов. Локальный журнал не получает содержимое посторонних вкладок, cookies или токены.
5. Сначала проверьте короткую задачу:

   > Открой https://example.com/ инструментом browser.open, извлеки текст browser.extract и заверши task.finish с кратким описанием найденного текста.

6. Проверьте, что в чате появились несколько последовательных запросов: команда открытия → результат → команда извлечения → результат → завершение. Сохранится `extract-<id>.json` и журнал.
7. Затем выполните исследовательскую задачу с конкретными URL:

   > Открой https://example.com/ и другие перечисленные мной URL. Собери тексты максимум пяти страниц через corpus.add. Сохрани корпус. Предложи категории контент-анализа с определениями и версией схемы. Прочитай необходимые фрагменты документов через corpus.read, разметь тексты точными цитатами. Посчитай частоты в Python и сохрани результаты через analysis.save. Укажи ограничения выборки и заверши task.finish.

Указывайте реальные текстовые HTML-страницы. `example.com` подходит только для проверки механики, а не для содержательного психологического исследования. Нельзя обещать, что бесплатный чат всегда выдаст корректный план или закончит длинную задачу.

## Настройка DeepSeek по живому интерфейсу

Адаптер не обращается к внутренним API, не извлекает токены и не решает CAPTCHA. Интеграция зависит от действующей разметки и правил сервиса. Пользователь обязан учитывать актуальные условия DeepSeek. Публичный чат может требовать вход, ограничивать частоту запросов или менять DOM.

Откройте DevTools вкладки DeepSeek → Elements. Найдите элементы и подберите устойчивые CSS-селекторы. Значения вводятся в рабочей вкладке расширения:

| Поле | Что должно находить |
|---|---|
| input | Единственное видимое поле сообщения: textarea, input или contenteditable |
| send | Видимую кнопку отправки; на пустом поле она может быть disabled |
| response | Контейнер каждого **финального ответа ассистента**, без блока рассуждений и сообщений пользователя |
| stop | Видимый признак текущей генерации, обычно кнопку остановки |
| complete | Маркер завершения **внутри последнего response**, например его панель действий |
| login | Видимый маркер необходимости входа |
| challenge | Видимый маркер CAPTCHA / необходимости участия человека |
| error | Видимый маркер ошибки сервиса / лимита |

Все восемь селекторов обязательны. Не заменяйте неизвестный маркер общим `body`, кнопкой другого назначения или заведомо фиктивным селектором. Для редких состояний (например, лимита) используйте селекторы только после наблюдения соответствующего интерфейса. Если их нельзя установить достоверно, **реальная интеграция остаётся непроверенной**. Ошибка CSS-селектора приводит к контролируемой паузе.

`response` должен включать только финальный ответ и панель завершения. Перед разбором JSON адаптер удаляет кнопки и узлы `complete` из копии контейнера. Если интерфейс смешивает рассуждения, текст ответа и посторонние подписи, потребуется доработка **только `src/deepseek-adapter.js`**. Диагностика показывает количество совпадений поля, ответа и кнопки, состояние и признаки завершения; содержание старого разговора в диагностику не выводится.

Состояния: ready, waiting-response, generating, completed, service-error, login-required, user-required. Завершение требует нового ответа относительно счётчика до отправки, маркера complete в последнем ответе, отсутствия stop и доступного composer. Два стабильных наблюдения текста используются дополнительно. Одна пауза в тексте завершением не считается. Если сайт не предоставляет надёжного маркера, адаптер не должен заменять его таймером — задача должна оставаться на паузе.

Проверьте вручную: пустой чат, длинный ответ с генерацией, готовый ответ, выход из аккаунта, наблюдаемый лимит и CAPTCHA. Последние состояния не обходятся. Не запускайте несколько агентов в одном чате.

## Что сохраняется

- `corpus.jsonl`: id, URL, ISO-время сбора UTC, заголовок, нормализованный текст, extractionMethod, SHA-256 текста. Дубликаты определяются по точному хешу нормализованного текста.
- `coding.csv`: documentId, category, quote, rationale, schemaVersion; UTF-8 с BOM, CSV-экранирование кавычек и запятых.
- `schema.json`: version и категории с определениями.
- `report.md`: отчёт модели плюс программно вычисленные частоты строк кодирования. Это частоты кодировок, не число уникальных документов. Несколько строк одного документа учитываются несколько раз.
- `execution.jsonl`: события исполнения и причины пауз.
- `prompts.json`: все фактически использованные запросы модели, включая запросы исправления JSON.
- `task-state.json`: состояние и результаты команд на момент последнего экспорта.
- `extract-<id>.json`: полные результаты явного browser.extract.
- `python-result-<id>.json`, `python/*`: результаты Python и настоящие файлы, включая PNG.

`analysis.save` перед записью проверяет точное вхождение **каждой** цитаты в текст документа и принадлежность категории схеме. Проверка не доказывает правильность интерпретации. Разметку и выводы должен проверить исследователь. Обработка персональных данных требует соответствующих оснований пользователя; агент их не устанавливает.

Чтение файломоделью разрешено для файлов, созданных текущей задачей, и путей, явно указанных пользователем в тексте задачи. `files.list` показывает не более 300 элементов верхнего уровня. Новые результаты создаются автоматически. При конфликте с пользовательским файлом или изменённым вручную результатом используется случайный суффикс, без перезаписи. Собственные неизменённые служебные результаты обновляются только при совпадении ранее сохранённого SHA-256. Полной защиты от одновременного редактирования файла другим приложением File System Access API не предоставляет: не редактируйте результаты во время записи.

## Пауза, остановка и восстановление

«Пауза» запрещает выдачу следующей команды, но даёт текущей операции закончиться. Ответ чата, пришедший во время паузы, сохраняется без исполнения. «Продолжить» использует его. «Остановить» отменяет ожидание, завершает Python Worker и отключает debugger. Уже отправленные внешние действия отменить невозможно; незавершённая команда остаётся помеченной для проверки.

Состояние сохраняется в IndexedDB после изменений; корпус не зависит от жизни service worker. В service worker нет агентного цикла и вычислений. Экспорт в выбранную папку выполняется после завершённых шагов и при выходе из цикла. Если доступ к папке отозван, локальное состояние в IndexedDB остаётся. Нажмите «Доступ к папке» в рабочей вкладке, подтвердите разрешение, затем продолжайте. Не удаляйте расширение и его данные: удаление может уничтожить IndexedDB и сохранённый handle.

После закрытия рабочей вкладки откройте управление снова. Незавершённая операция не выполняется повторно автоматически. В разделе восстановления:

1. Для неопределённой отправки проверьте **тот же чат**. «Принять завершённый ответ из чата» принимает только новый завершённый ответ относительно сохранённого счётчика. Если отправки не было, очистите поле вручную и используйте «Сбросить неопределённую отправку» после проверки истории. Не сбрасывайте запрос, если он мог отправиться.
2. Для незавершённой команды проверьте вкладку и файлы. Укажите фактический результат и нажмите «Зафиксировать ручную проверку команды». Её id попадёт в реестр выполненных/сверенных команд; результат проверки передастся модели как структурированная ошибка. Даже неуспешная команда с этим id больше не повторяется.
3. После **перезапуска браузера или перезагрузки расширения** заново подключите DeepSeek. Рабочие вкладки прошлого сеанса не считаются принадлежащими задаче: нажмите «Забыть вкладки прошлого сеанса»; они останутся открыты, агент создаст новые. Это защищает от повторного использования Chrome ID для чужой вкладки. После сброса старые команды snapshot дадут ошибку, модель должна открыть новые страницы.
4. Лимит 30 минут считается от создания задачи и сохраняется при восстановлении. Если он истёк, начните новую задачу, указав нужные сохранённые файлы. Старая задача архивируется в IndexedDB, файлы не удаляются. Автоматического импорта произвольного task-state.json в MVP нет.

Debugger отключается на паузе/окончании/остановке. Его ручное отключение или закрытие рабочей вкладки ставит задачу на паузу. Изменение DOM или ввод инвалидирует snapshot. Во время работы не взаимодействуйте с рабочими страницами: ручное прокручивание и изменения, не затронувшие DOM, не всегда можно отличить от действия агента. Удобнее сначала поставить паузу.

## Границы автономности и лимиты

Чтение указанных пользователем URL, извлечение, корпус, вычисления и создание новых файлов автоматические. Открытие URL, отсутствующего в задаче, требует подтверждения. Все click/type в MVP консервативно требуют подтверждения конкретного действия: невозможно надёжно определить побочный эффект произвольной кнопки или обработчика сайта. Показаны команда, аргументы и цель. Никаких платежей или публикаций без такого подтверждения. Удаление файлов инструментами не поддерживается.

- Одна активная задача; 50 шагов, пять созданных рабочих вкладок / документов корпуса, 30 минут; повтор одной команды по id пропускается.
- Не более двух исправлений JSON подряд. Три повтора одинакового действия допустимы, четвёртый за последние восемь шагов приводит к паузе.
- CDP — 20 секунд на команду; DOM DeepSeek — 15 секунд; генерация — 180 секунд; Python — 60 секунд. Проверка Python в тестах даёт до 90 секунд на холодный старт.
- Сообщение модели — максимум 45000 символов. Результаты ограничены 14000 символами с явным truncated; полные извлечения и Python-результаты сохранены локально. Чтение файлов/корпуса — до 12000 символов за запрос с offset.
- Snapshot: основной текст до 9000 символов, до 80 элементов. Extract: до 500 ссылок; 30 таблиц, 300 строк, 40 столбцов; усечение помечается. Более 300000 символов в одном extract отклоняется, без скрытой потери текста корпуса.
- Файлы чтения/записи — до 10 МБ; Python экспортирует до 30 файлов, каждый до 5 МБ. stdout/stderr — 50000 символов с флагами усечения. Общая память WebAssembly ограничивается браузером, отдельного надёжного квотирования памяти Python нет.
- URL только HTTP(S), без credentials, query и hash. Такое ограничение защищает от случайной отправки токенов URL; сайты с параметрами URL требуют доработки правил. Вкладка DeepSeek исключена из browser-инструментов.
- Только HTML, без OCR, PDF, canvas, iframe-обхода и виртуализированных сложных приложений. Извлечение — DOM основного текста, а не полноценный Readability. `browser.type` добавляет текст в выбранное поле; пароли, upload и специальные input запрещены.

Текст сайта не получает полномочия: в коде проверяются пути, принадлежность вкладки текущему сеансу/задаче, разрешённые инструменты, явные файлы и необходимость подтверждения. Промпт также маркирует данные как недоверенные. Это уменьшает последствия prompt injection, но не доказывает качество плана или анализа модели.

## Python и локальные зависимости

Pyodide **0.27.7**, Python 3.12.7. В `vendor/pyodide/` находятся готовые JS/WASM, стандартная библиотека, lock-файл и все 14 wheel-пакетов набора NumPy 2.0.2, pandas 2.2.3, matplotlib 3.8.4 с зависимостями. Никаких загрузок кода во время использования. SciPy, pip и произвольные внешние пакеты не включены. Базовая статистика — `statistics` и NumPy; графики — matplotlib Agg.

Каждая команда создаёт свежий Worker в sandbox-странице с непрозрачным origin. Передаются только code и JSON data; код читает переменную `data`, присваивает JSON-совместимый `result` и сохраняет файлы в `/results`. Пример:

```python
import pandas as pd
import matplotlib.pyplot as plt
frame = pd.DataFrame(data['rows'])
counts = frame['category'].value_counts()
counts.plot.bar()
plt.tight_layout()
plt.savefig('frequencies.png')
result = {str(k): int(v) for k, v in counts.items()}
```

Нет mountNativeFS, системных процессов, нативных ОС-библиотек и доступа к host-файлам. `import js` существует в Pyodide, поэтому изоляция выполнена **origin и CSP**, а не запретом строки импорта. Python не получает directory handle, Chrome API или IndexedDB расширения. Внешняя сеть в sandbox запрещена CSP; разрешены только ресурсы установленных расширений (`chrome-extension:`), необходимые для загрузки локального Pyodide. Только статические packaged URL попадают в короткий Blob-bootstrap Worker; пользовательский JavaScript в него не подставляется. В собственном JS нет eval или Function. `'wasm-unsafe-eval'` разрешает компиляцию WASM, не JS-eval. Upstream-дистрибутивы поставляются в официальном формате; собственные модули не минифицированы.

Происхождение: `https://cdn.jsdelivr.net/pyodide/v0.27.7/full/`. `SHA256SUMS` фиксирует скачанные байты; SHA-256 всех 14 wheel-файлов дополнительно совпал с официальным lock-файлом. Лицензии core и Python — в vendor; лицензии пакетов также находятся внутри wheel в dist-info.

## Архитектура и протокол

| Модуль | Ответственность |
|---|---|
| DeepSeekAdapter | DOM-селекторы, диагностика, вставка/отправка, признаки завершения, запрет слепой повторной отправки |
| AgentController | Одна команда за цикл, валидация, реестр id, лимиты, пауза, сверка, контекст |
| BrowserTools | tabs + chrome.debugger/CDP, isolated world, snapshot, ссылки на элементы, extraction |
| ProjectFiles | File System Access API, границы путей, проверки разрешений, конфликты имён |
| PythonRuntime | MessageChannel → sandbox → Worker → локальный Pyodide, таймаут, отмена |
| StateStore | IndexedDB состояния, handles и реестра файлов; краткое состояние в chrome.storage.local |
| UI | Боковая панель открывает единственную рабочую вкладку, где живёт цикл и файловые разрешения |

Команда — ровно четыре поля:

```json
{"id":"step-1","tool":"browser.open","args":{"url":"https://example.com/"},"description":"Открыть источник"}
```

Успех: `{"id":"step-1","status":"ok","data":{"tabId":123}}`. Ошибка: `{"id":"step-1","status":"error","error":{"code":"TOOL_FAILED","message":"..."}}`.

`protocol.js` содержит полный реестр и проверяет точные поля args. Помимо browser.*, files.* и python.run есть независимые corpus.add/read, analysis.save и task.finish. Исследовательские функции — дополнительные инструменты, а не единственный зашитый workflow: задача может только читать сайты, сохранять произвольные результаты или выполнять Python. Системное сообщение описывает доступные инструменты заново и включает компактное локальное состояние и результат предыдущего шага; полная история инструментов не раздувает каждое сообщение. Сам веб-чат сохраняет свой разговор: при исчерпании его контекста нужна ручная новая сессия и проверка состояния.

## Проверки без установки зависимостей

Откройте из рабочей вкладки «Локальные проверки» → «Выполнить проверки». Откроются и закроются тестовые вкладки, Python загрузится из vendor. Тесты используют отдельную IndexedDB `psy-agent-tests` и приватную OPFS-папку браузера; выбранная исследовательская папка и реальная задача не затрагиваются. Они не обращаются к DeepSeek и не являются режимом модели в основном интерфейсе.

Проверяются: протокол, пути, URL, конфликты/отзыв разрешений, восстановление, DOM/навигация/пагинация, свежесть элементов, текст/ссылки/таблицы, DOM-чата, Python/PNG/изоляция, таймаут/остановка, дубликаты, исправление JSON, верификация цитат и сквозные corpus→coding→report с тестовой моделью. Результаты доступной автоматической проверки — `VALIDATION.md` и `tests/last-results.json`.

Ручная приёмка дополнительно обязательна:

1. Установка папки, отсутствие ошибок manifest/CSP; боковая панель и одна рабочая вкладка.
2. Все тесты в extension-origin, включая sandbox Worker и chrome.debugger.
3. Выбор **обычной** папки через реальный picker; файл создаётся на диске. Пользовательский `report.md` не изменяется при конфликте.
4. Реальный DeepSeek: диагностика и короткий вертикальный сценарий из раздела первого запуска. Проверить, что инструментальный результат действительно вернулся в чат.
5. Несколько HTML-источников → корпус/схема/CSV/отчёт/частоты. Сверить сохранённые цитаты с корпусом.
6. Пауза во время генерации, stop во время Python, отключение debugger, закрытие рабочей вкладки, восстановление разрешений папки.
7. Перезагрузка расширения и перезапуск браузера: корпус остаётся, неопределённые шаги заблокированы, чужие вкладки не управляются.

## Редактирование без сборки

Измените JS/HTML/CSS обычным редактором. На `chrome://extensions` нажмите «Обновить» на карточке расширения. Закройте и снова откройте рабочую вкладку и боковую панель; при изменении логики DOM переоткройте также рабочие страницы и подключите DeepSeek заново. Сначала поставьте задачу на паузу. Не удаляйте расширение ради обновления — это может стереть состояние. Не переименовывайте постоянно папку расширения: Chrome может выдать другой extension ID и отдельное хранилище.

CSP/Worker/Manifest V3 учтены по официальной документации Chrome: `https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy`, `https://developer.chrome.com/docs/extensions/reference/manifest/sandbox`, `https://developer.chrome.com/docs/extensions/reference/api/debugger`. В среде прочитаны исходники документации Chrome о minimum CSP (`'self' 'wasm-unsafe-eval'`) и debugger; реальная extension-origin проверка заблокирована администратором, поэтому совместимость не выдаётся за подтверждённую на целевых Windows/macOS.

## ZIP через GitHub Actions

Загрузите **содержимое этой папки** в корень GitHub-репозитория: `manifest.json` и `.github/` должны лежать в корне. Локальная папка `vendor/` тоже должна попасть в репозиторий, включая WASM и wheels. Не включайте для них Git LFS: упаковщик проверяет реальные байты зависимостей.

Workflow `.github/workflows/package.yml` запускается на push, pull request и вручную через **Actions → Package Chrome extension → Run workflow**. Он проверяет синтаксис собственного JavaScript, manifest, наличие локальных ресурсов и контрольные суммы Pyodide, затем упаковывает исходники без сборки и без загрузки зависимостей. Python из стандартной поставки GitHub runner используется только для ZIP; на компьютере пользователя он не нужен.

После успешного запуска откройте его страницу → **Artifacts** → `psy-agent-<commit SHA>`. GitHub скачает контейнер артефакта с `psy-agent.zip` и `psy-agent.zip.sha256`. Распакуйте внутренний ZIP и загрузите папку `psy-agent` через `chrome://extensions`. Артефакты хранятся 30 дней. При push тега `v*` после успешной упаковки автоматически публикуется предварительный GitHub Release с ZIP и SHA-256. Только job публикации получает `contents: write`; остальные проверки имеют доступ лишь на чтение. Повторный запуск публикации обновляет вложения этого тега. Для нового выпуска создайте тег, например `git tag v0.1.1`, затем отправьте его: `git push origin v0.1.1`.

CI не входит в DeepSeek и не выполняет браузерную приёмку: успешная упаковка не подтверждает работу реального чата. Для разработки по-прежнему достаточно редактирования исходников и перезагрузки расширения.
