# Агент для веб-чата DeepSeek

Chrome Manifest V3, обычные JavaScript ES-модули, HTML и CSS. Расширение добавляет к веб-чату инструменты браузера, файлов и Python и выполняет агентный цикл. Платного API, backend, npm, сборки и системного Python для пользователя нет.

## Установка и использование

1. Распакуйте ZIP в постоянную папку. В Chrome Windows/macOS откройте `chrome://extensions`, включите режим разработчика и загрузите папку с manifest.json.
2. Откройте DeepSeek и самостоятельно войдите. После установки или обновления расширения перезагрузите страницу DeepSeek.
3. Над полем ввода появятся переключатель **Агент**, короткий статус и значок **⚙**. Панель не перекрывает переписку. Значок расширения также открывает настройки в отдельной вкладке.
4. Откройте настройки и выберите хранилище через **Результаты → Выбрать**: отдельную папку устройства или внутреннее хранилище браузера. Не выбирайте папку расширения или каталог с секретами. Подключение к открытому чату определяется автоматически.
5. Распознавание элементов автоматическое. Если интерфейс неоднозначен, используйте необязательный мастер **Дополнительно → Привязать интерфейс**: поле сообщения, отправка, текст готового ответа и его кнопка копирования. CAPTCHA и ошибки выбирать не нужно.
6. Новую задачу можно отправить после остановки предыдущей: старая задача архивируется вместе с неопределёнными действиями, которые не выполняются повторно. Настройки можно закрыть. Вернитесь в DeepSeek, включите «Агент», напишите задачу обычным полем и отправьте кнопкой или Enter. Shift+Enter оставляет перенос строки.
7. Расширение перехватит отправку, сохранит задачу, добавит инструкцию с инструментами, затем будет выполнять команды модели и отправлять результаты обратно в тот же чат. **Выключение переключателя останавливает цикл и Python.** Подтверждённый контроллером финальный ответ отображается обычным текстом в чате. Служебные запросы и JSON-команды скрыты, полные данные сохранены локально. В переписке остаётся читаемая история: описание действия, выполнение, подтверждённый результат или ошибка. История берётся из локального состояния, а не из заявлений модели, и восстанавливается при открытии беседы. Над полем ввода показаны текущая фаза, время ожидания или краткая причина паузы. При выключенном режиме обычная отправка DeepSeek сохраняется.

Сохранённые привязки используются как подсказки; при их устаревании применяются семантические признаки поля, кнопок и сообщений. Для разметки из пользовательского экспорта DeepSeek от 01.11.2026 добавлен профиль: область ввода, SVG-иконки отправки/копирования и `ds-assistant-message-main-content`. Он проверен на сохранённом DOM, без сетевых запросов. Один распознаватель используется и перехватчиком отправки, и адаптером. Неизвестная иконка основной кнопки блокирует отправку; её нельзя автоматически считать известной кнопкой остановки. Завершение требует панели действий ответа, доступности режима отправки и стабильного нового текста. При изменении сайта может потребоваться обновление профиля или ручной мастер. Живая отправка в авторизованный DeepSeek и работа на устройстве Titanium пока не проверены.

## Titanium и другие мобильные Chromium

Сайдбар не используется. Переключатель и настройки находятся над полем ввода DeepSeek; кнопки рассчитаны на касания, есть мобильный viewport и экранная отмена мастера. Версия/сборка Titanium пользователя пока неизвестна, поэтому поддержка конкретных API не предполагается автоматически.

1. В настройках откройте **Результаты → Выбрать/Изменить → Внутри браузера**, если выбрать папку нельзя. Рабочие файлы сохраняются в OPFS. Доступ к обычной файловой системе телефона не требуется.
2. Вернитесь в DeepSeek и включите «Агент». Включение режима означает, что задача и выбранные данные отправляются в этот чат; отдельного переключателя согласия нет. При первом включении показано краткое уведомление.
3. Режим **Автоматически** использует CDP, а при его недоступности переходит на стандартные API страниц. Если для них нужен доступ к сайтам, в настройках появляется строка **Доступ к страницам → Предоставить**. Запасной ручной выбор режима, привязка и диагностика находятся в **Дополнительно**.
4. Закройте настройки и выполняйте задачу в DeepSeek. Для скачивания результатов откройте **Файлы** в настройках и нажмите «Скачать». Для списка файлов и скачивания работающий агент не нужен.

Совместимый режим использует chrome.scripting: чтение, snapshot, прокрутка, программные click/input. Он не требует CDP, но сайты могут не принимать программные события. Текстовые поля и побочные действия проверяются теми же правилами, ссылки на элементы инвалидируются после изменения DOM. Нужны tabs, scripting, storage.session, IndexedDB, Web Locks, Worker и WASM. Их отсутствие — реальное ограничение конкретного браузера, а не настройка селекторов.

Держите чат на экране во время выполнения. Перенос исполнителя в активную вкладку убирает зависимость от фоновой вкладки настроек, но не предотвращает выгрузку приложения Android, блокировку телефона или ограничения памяти. Pyodide с pandas/matplotlib может быть тяжёлым для телефона. Смена хранилища не переносит уже созданные файлы. Результаты внутреннего хранилища скачайте до удаления расширения или очистки данных браузера.

## Протокол и инструменты

«Системный промпт» здесь — обычное сообщение с инструкцией в веб-чате, а не настоящий API system-role. Расширение не может менять внутренние системные инструкции DeepSeek. В промпте нет сценариев контент-анализа или психологических рекомендаций.

Доступные модели инструменты: browser.open/snapshot/inspect/collect/click/type/scroll/extract, files.list/read/write, python.run/status/cancel и task.finish. Модель возвращает один JSON:

```json
{"id":"step-1","tool":"browser.open","args":{"url":"https://example.com/"},"description":"Открыть источник"}
```

Результат содержит тот же id, статус и data либо структурированную ошибку. task.finish содержит итоговый ответ в summary. В интерфейсе видны история шагов контроллера и итоговый ответ после успешного завершения задачи. Служебный текст остаётся в DOM для адаптера и в локальном журнале. Геометрия ещё не принятого ответа сохраняется: его сворачивание не должно скрыть признаки завершения от адаптера. Локальное представление истории хранит до 50 последних задач; полные журналы задач остаются в выбранном хранилище. Каждый ответ проходит валидацию до выполнения; завершённый id повторно не исполняется. Некорректный JSON получает до двух запросов исправления.

Старые corpus/analysis обработчики сохранены для совместимости с локальными тестами и ранее сохранёнными данными, но не включаются в описание инструментов новой задачи. Любой анализ пользователь задаёт собственным запросом; общие files и python подходят для CSV, отчётов и вычислений.

## Данные, разрешения и ограничения

В DeepSeek передаются задача, извлечённые тексты и результаты инструментов. Полные извлечения и вычисления сохраняются в выбранной папке, большие результаты передаются фрагментами с признаком truncated. Файлы чтения должны быть созданы задачей, явно названы пользователем или выбраны моделью через files.list внутри папки проекта. Во время выполнения нет диалогов подтверждения. Изменение данных сайта, публикации, покупки и удаления недоступны и возвращают модели ошибку; она может продолжить другим способом.

Рабочие вкладки создаются отдельно от вкладки модели. Управление через chrome.debugger/CDP ограничено текущей задачей и сеансом браузера; специального debug-порта нет. После изменения DOM ссылки на элементы устаревают. Не меняйте разговор и не взаимодействуйте с рабочими вкладками во время цикла.

Сторонний текст не расширяет полномочия: проверяются аргументы, пути и принадлежность вкладок. Поддерживаются HTML-страницы; нет OCR, PDF, canvas и обхода iframe. Разрешены HTTP(S), параметры поиска и фрагменты. Запрещены credentials, вкладка DeepSeek и явные параметры авторизации (token, password и аналогичные). Автоматически доступны обычные ссылки, поля поиска и элементы раскрытия; произвольные кнопки изменения данных и обычные поля форм блокируются до взаимодействия. Встроенные локальные фикстуры могут тестировать остальные элементы. Чтение, вычисления и новые файлы выполняются автоматически.

Новые результаты при конфликте получают новое имя. Только собственные неизменённые служебные результаты обновляются по сохранённому хешу. Пользовательские файлы не удаляются. Не редактируйте результаты параллельно записи: File System Access API не обеспечивает транзакции с внешними приложениями.

Число шагов и общая длительность задачи не ограничены. Старую задачу, остановленную прежними лимитами, можно продолжить сообщением «продолжай» после обновления; счётчик и результаты сохраняются. Убрано и искусственное ограничение расширения в 45000 символов на запрос. Реальные ограничения веб-чата зависят от DeepSeek; перед отправкой проверяется, что поле содержит полный вставленный запрос. В каждый контекст входят последние 20 путей файлов и их общее число; остальные доступны через files.list, без удаления данных. Сохраняются ограничения отдельных операций: 5 рабочих вкладок одновременно, CDP 20 секунд, ожидание ответа модели 180 секунд. У Python нет автоматического ограничения времени запуска или вычисления. Повторяющиеся команды без прогресса приводят к паузе. Ожидание одного ответа имеет общий бюджет 180 секунд, включая автоматическую сверку после временной DOM-ошибки. Таймаут не запускает ещё одно трёхминутное ожидание. Если чат показывает готовность, но 45 секунд нет нового текста или признаков завершённого ответа, задача ставится на понятную паузу. Активная генерация имеет общий лимит 180 секунд. Виртуализированный ответ расширение пытается показать прокруткой к концу беседы; запрос при этом не отправляется повторно. Результаты browser.extract ограничены 300000 символами, snapshot — 9000 символами/80 элементами. files.read возвращает до 12000 символов с offset. Усечение обозначается явно.

## Python

Локальный официальный Pyodide 0.27.7 / Python 3.12.7, NumPy 2.0.2, pandas 2.2.3, matplotlib 3.8.4 и зависимости уже находятся в vendor. Контрольные суммы wheels сверены с официальным lock-файлом. Библиотеки загружаются только из vendor и только если импортируются кодом. Для простого Python NumPy/pandas/matplotlib не инициализируются.

python.run запускает фоновую задачу и сразу возвращает jobId. Модель получает состояние через python.status(jobId, waitMs?), может параллельно собирать другие страницы и отменить вычисление через python.cancel(jobId). waitMs до 15000 — длительность ожидания нового статуса, а не предел работы Python. Доступны фаза запуска/выполнения, общее время, время кода, давность последнего события, хвосты stdout/stderr и сообщения progress(...). Прошедшее время само по себе не считается признаком зависания. Перед task.finish модель должна дождаться результата или отменить задачу.

В длительном коде можно вызывать `progress("Обработано 50 из 100")` или `progress({"done": 50, "total": 100})`. `print()` также передаётся во время работы. В чате обновляется одна строка истории этого вычисления; служебные проверки статуса скрыты. Автоматического таймаута Python нет. Выключение «Агент» отменяет и фоновый Python, в том числе когда сам цикл агента приостановлен. Пауза цикла сохраняет уже начатое вычисление.

python.run получает code, JSON data и необязательный список files=[{path,name}]. Расширение загружает эти файлы из папки проекта и передаёт копии напрямую в Worker; содержимое не требуется переписывать в сообщение DeepSeek. В Python data содержит небольшие параметры, inputs[name] — путь к копии файла в /inputs. Оригинальные файлы не монтируются и не изменяются. Worker создаётся в sandbox с непрозрачным origin без Chrome API, IndexedDB и directory handle. CSP запрещает внешнюю сеть; доступны только локальные зависимости. Каждый вызов получает новый Worker.

Пример чтения результата сбора:

```python
import json
import pandas as pd

doc = json.load(open(inputs["page.json"], encoding="utf-8"))
table = pd.DataFrame([row["fields"] for row in doc["records"]])
table.to_csv("data.csv", index=False)
result = {"rows": len(table)}
```

Файл data.csv экспортируется в tasks/<taskId>/python/step-<commandId>/data.csv. Вход: до 20 файлов, каждый до 10 МБ, суммарно до 20 МБ. Выход: до 30 файлов, каждый до 5 МБ, суммарно до 20 МБ; stdout/stderr до 50000 символов с флагами усечения. После вычисления полный результат сначала фиксируется в IndexedDB и очереди выгрузки, затем сохраняется в папку. Если выгрузка прервалась, следующий python.status или запуск агента довыгружает данные без повторного кода и дубликатов. Уже экспортированные результаты и исходные файлы сбора остаются при остановке. После закрытия вкладки незавершённый Worker обозначается как прерванный и не перезапускается автоматически.

## Сбор по плану и сохранение каждой страницы

Модель сама вызывает browser.inspect, получает теги, безопасные атрибуты и кандидаты селекторов, затем вызывает browser.collect с планом контейнера и полей. План допускает только чтение DOM: нет JavaScript, кликов, запросов, cookies или значений форм. Поддерживаются текст и фиксированный набор атрибутов, до 500 записей и 20 полей. Пропущенные поля — null, усечение обозначается явно. Протокол и ограничения описаны в [EXTRACTION.md](EXTRACTION.md).

Открытие с полученным snapshot, отдельный snapshot, extract и collect автоматически сохраняются **до следующего шага** в tasks/<taskId>/pages/step-<commandId>.json. Сохраняются данные, URL, время, метод, хеш и план сбора. Для полного текста нужно использовать extract/collect: snapshot по-прежнему компактный и может быть усечён. Журнал и состояние лежат в tasks/<taskId>/; разные задачи не перезаписывают друг друга. Модель получает путь и короткий просмотр, Python читает полный файл.

При остановке уже начатая запись страницы завершается. Перед записью полный результат атомарно фиксируется в IndexedDB; если экспорт прервался, он восстанавливается при продолжении из этого журнала. Новый запуск также довыгружает отложенные результаты архивных задач в текущее выбранное хранилище. Повторное чтение сайта для этого не нужно. Совпавший пользовательский файл получает новое имя, оригинал не перезаписывается.

Чтобы файлы находились в обычной папке устройства, выберите её кнопкой выбора папки в настройках. Если выбран режим «Внутри браузера», те же пути относятся к внутреннему хранилищу OPFS; это не папка устройства, файлы доступны для скачивания. Поддержка выбора папки зависит от браузера и видна в настройках.

## Рабочая вкладка

browser.open сначала выбирает рабочую вкладку с уже открытым URL, иначе переводит последнюю рабочую вкладку на новый URL. Если URL уже открыт, вкладка не перезагружается. Следующая задача перенимает подтверждённые рабочие вкладки предыдущей в том же сеансе браузера. Отдельная вкладка создаётся только при отсутствии рабочей либо по явному аргументу newTab=true, например для сравнения страниц; максимум пять одновременно. DeepSeek и вкладки без подтверждённой принадлежности расширению не переиспользуются. Вкладки с незавершёнными взаимодействиями не передаются новой задаче.

При переиспользовании сохраняется журнал перехода. Ожидание готовности отличает старый документ от нового и учитывает редиректы; старая страница не считается завершившей новый переход. Файлы сбора предыдущей страницы остаются в папке независимо от навигации.

## Ожидание страниц

Перед snapshot/extract и после click/type/scroll расширение ждёт готовности DOM (`interactive`/`complete`, после разбора HTML) и стабильности основного содержимого. Проверки идут примерно каждые 250 мс: сравниваются текст и геометрия его блоков с допуском 2 пикселя. Нужно около секунды без изменений, минимум 1,2 секунды наблюдения. Учитываются видимые индикаторы загрузки и незагруженные изображения в области просмотра. Меню, часы в time и явно размеченная реклама исключены; небольшие изменения таких блоков не сбрасывают ссылки snapshot.

Лимит ожидания — 15 секунд. По таймауту возвращаются текущие данные с readiness.ready=false и причиной, цикл не останавливается. Сеть и событие window.load не являются условием готовности. Смена документа/URL сбрасывает наблюдение, остановка агента отменяет ожидание. Это проверка DOM и геометрии, без скриншотов; она не гарантирует полноту поздних загрузок, игнорирует цветовые анимации и не анализирует canvas/iframe. На больших страницах объём пробы ограничен, о чём сообщает sampleLimited.

## Восстановление

Состояние и результаты хранятся в IndexedDB; execution.jsonl, prompts.json и task-state.json экспортируются в выбранное хранилище. Настройки можно закрыть. После закрытия/выгрузки чата откройте исходную беседу, включите агент и напишите **«продолжай»**. Это продолжает ту же задачу. Новое сообщение с другой задачей архивирует старую и начинает отдельный запуск.

Перед продолжением расширение сверяет незавершённый шаг: использует сохранённый результат, проверяет хеш файла или находит созданную командой вкладку. Оно не повторяет неизвестный клик или Python-код. Если подтвердить результат нельзя, команда получает ошибку, а модель выбирает другой путь; чтение и остальной цикл остаются доступны. Вкладка с неподтверждённым взаимодействием остаётся доступна для чтения, повторные click/type в ней блокируются. Старые вкладки, которые больше нельзя подтвердить в текущем сеансе, удаляются из рабочего списка без закрытия вкладок пользователя.

Отправленный запрос DeepSeek восстанавливается чтением истории и ожиданием ответа. Доказанно не отправленный черновик можно отправить один раз. Если доказательств доставки нет, запрос не отправляется повторно; позже можно снова написать «продолжай» или дать новую задачу. CAPTCHA, вход и отозванное разрешение на папку требуют действий в самом браузере/сервисе. При отзыве разрешения на папку в настройках появляется **Доступ к папке → Предоставить**; ручная сверка команд в настройках не является обычным способом продолжения.

Выбор папки и разрешение на неё — разные вещи. Расширение сохраняет выбор в IndexedDB и переиспользует живой дескриптор между запусками, продолжениями и файловыми операциями. Если доступ уже разрешён, повторный requestPermission не вызывается. Явное предоставление доступа обновляет сохранённый дескриптор для остальных вкладок расширения. Отзыв разрешения проверяется при каждой операции; приложение не выдаёт разрешение само себе.

После перезапуска, выгрузки или обновления расширения браузер может потребовать разрешение заново. Если он предлагает постоянный доступ, можно выбрать его. На Titanium сохранение этого разрешения между сеансами не проверено. Режим **Результаты → Изменить → Внутри браузера** использует OPFS и не запрашивает доступ к папке устройства; результаты из него скачиваются через «Файлы».

Не удаляйте расширение ради обновления: это может уничтожить IndexedDB. После правок исходников достаточно «Обновить» в chrome://extensions и переоткрыть настройки/страницу DeepSeek. Сборка не требуется.

## Проверки и известные границы

`tests/index.html` запускает локальные проверки без npm и сервера. Тестовые данные находятся в отдельной IndexedDB и OPFS, пользовательская папка не затрагивается. Также в разработческом Chromium проверены перехват настоящего клика и Enter, обычная отправка при выключенном режиме, выключение агента, мастер четырёх кликов и пропуск программной отправки адаптера.

В этой среде администратор запрещает загрузку unpacked-расширений. Проверки выполнялись через HTTP-стенд и настоящий CDP с заменённым транспортом Chrome API. Контур content script → service worker → исполнитель в iframe → Python проверен с подменённым транспортом Chrome API. Текущий авторизованный DeepSeek, extension-origin iframe в установленном расширении, реальный выбор пользовательской папки и устройства Windows/macOS/Titanium требуют ручной приёмки. Бесплатный чат может менять интерфейс и вводить ограничения. Токены не извлекаются, внутренние API не используются, CAPTCHA не обходится.

Совместимость Python: среда подтверждает готовность через отдельный обмен сообщениями; ошибки Worker/CSP/WASM возвращаются с указанием этапа. При отсутствии instantiateStreaming или неправильном MIME файла .wasm используется обычный WebAssembly.instantiate над теми же локальными байтами. Политика CSP и изоляция не ослабляются. Поддержка самого WebAssembly и Worker браузером остаётся обязательной.

Архитектура: chat-ui.js — переключатель, перехват и мастер; workspace.js — настройки и скачивание результатов; service-worker.js — проверка отправителей и маршрутизация; executor.js — выполнение в iframe чата; DeepSeekAdapter — DOM чата; AgentController — цикл; BrowserTools — CDP; ProjectFiles — папка; PythonRuntime — sandbox Worker; PythonJobs — фоновые задачи, прогресс и долговечная выгрузка; StateStore — состояние; dom-collector.js — план чтения DOM; captures.js — журнал и выгрузка страниц; python-inputs.js — контролируемая загрузка файлов. Описание проверок и их границ — [VALIDATION.md](VALIDATION.md).

## GitHub Actions

В корне репозитория должны находиться manifest.json, .github и vendor. Workflow проверяет синтаксис JS, manifest и контрольные суммы, затем упаковывает существующие файлы. На push/PR доступен Artifact с ZIP и SHA-256, срок хранения 30 дней. Push тега v* публикует предварительный Release; право contents:write получает только job публикации. Python на GitHub runner нужен лишь упаковщику, пользователю устанавливать его не требуется.
