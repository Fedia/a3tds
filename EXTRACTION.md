# Сбор DOM и входные файлы Python

Настраивать CSS пользователю не требуется. Он формулирует задачу, например: «Собери отзывы с этих страниц, сохрани автора, дату и текст, затем посчитай частоты слов в Python и сохрани CSV».

## Инспекция и план

`browser.inspect` принимает tabId, selector (например, main или body), limit от 1 до 100. Возвращает inspection, видимые теги/атрибуты, глубину, короткий текст и кандидаты селекторов с числом совпадений. Объём ответа ограничен; модель может уточнить блок новым вызовом. Полный HTML, скрипты и значения полей ввода не передаются.

`browser.collect` принимает tabId, inspection и plan:

```json
{
  "container": ".review",
  "fields": {
    "author": {"selector": ".author", "attribute": "text"},
    "date": {"selector": "time", "attribute": "datetime"},
    "text": {"selector": ".body", "attribute": "text"}
  },
  "limit": 500
}
```

Контейнеры выбираются только внутри исследованного блока. Селекторы полей относятся к каждому контейнеру; `:scope` означает сам контейнер. Значения: text, href, src, title, alt, datetime, aria-label, data-id, data-name, data-author, data-date, data-rating, data-price. HTTP(S)-ссылки приводятся к абсолютным; ссылки с credentials или явными параметрами авторизации не выдаются. Нет произвольных атрибутов, JS, сетевых запросов или взаимодействий.

После перехода на другую страницу нужен новый inspect. Инспекция не гарантирует, что выбранные моделью селекторы правильно отражают смысл данных; проверить это можно по примеру записей и счётчикам missing/totalMatched.

Сохраняются records с id, fields и source, план, URL, заголовок, время, метод и capture с идентификатором задачи и хешем содержимого. Отсутствующие поля — null. До 500 записей, 20 полей, 20000 символов в поле, около 2000000 символов данных записей. Признак truncated указывает на ограничение; это не полная копия страницы. Нет OCR, PDF, canvas, вложенных iframe и Shadow DOM. Текст нормализуется по пробелам.

## Прямой вход в Python

Дополнительный аргумент python.run:

```json
{
  "files": [
    {"path": "tasks/<taskId>/pages/step-<commandId>.json", "name": "page.json"}
  ]
}
```

code обязателен; data по умолчанию {}. Полный вызов валидируется как остальные команды. Расширение само читает указанный файл и передаёт байты Worker; модель не копирует содержимое в data. `inputs["page.json"]` указывает на отдельный путь копии этого запуска внутри `/inputs/`. data используется для небольших параметров вычисления.

files.list без path перечисляет корень, с path — указанную подпапку проекта. После перечисления доступны файлы этой папки. Передача произвольных путей вне проекта запрещена. Worker и пользовательские переменные сохраняются в общей Python-сессии; новые входные файлы передаются явно через files. Изменение копии в /inputs не изменяет оригинал. Экспортируются только файлы из /results, относительные пути повторно проверяются расширением.

## Остановка и сбой

Каждый полученный результат чтения сохраняется в отдельный JSON, затем возвращается модели путь. Snapshot хранит только свой ограниченный текст; полный текст читается через extract или выбранные поля collect. Начатая запись закрывается даже после stop. При прерывании экспорта остаётся локальный журнал полного результата; продолжение выгружает его без повторного сбора страницы. Старт новой задачи не удаляет уже экспортированные файлы прошлой задачи.

Для обычной папки устройства нужен режим выбора папки File System Access. В режиме OPFS файлы находятся внутри браузера и доступны через скачивание; удаление расширения может удалить внутренние данные. Для переноса на другое устройство сохраняйте папку результатов.
